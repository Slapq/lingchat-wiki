# 🔌 插件安装与使用指南

插件是放在 `data/plugins/<id>/` 下的独立目录，用 `manifest.toml` 声明能力。安装并启用后，它可以做两件事：

- **给 AI 增加工具**：插件声明的工具会注册进工具列表，由模型在对话中调用。
- **给游戏增加内容**：角色、剧本、音乐、背景图、环境音会直接混入对应列表，并带「插件」来源角标。

本页讲「拿到插件之后怎么装、怎么开」。想自己写插件，见 [Python 插件开发指南](/creator/plugin-development)。

## 两种安装方式

### 方式一：从压缩包导入（推荐）

入口：`设置 → 插件 → 从压缩包导入插件`

1. 先选「同名插件处理方式」：
   - **覆盖**：同名插件的本体、配置与启用状态一起清除，等同于全新安装。
   - **放弃**：检测到同名插件就中止，不落盘、不动已有插件。
2. 点击「选择 zip / 7z 并导入」，选中压缩包。
3. 导入进度会在页面底部显示，完成后插件出现在上方列表——**默认是关闭的**，需要手动打开开关。

压缩包里的文件名不参与命名：后端以 `manifest.toml` 的 `id` 创建目录，所以不存在「导入时顺便改名」这种选项。

### 方式二：手动放入目录

把整个插件文件夹放进 `data/plugins/`：

```text
data/
└── plugins/
    └── my_plugin/            # 目录名必须等于 manifest.toml 里的 id
        ├── manifest.toml     # 必须
        ├── main.py           # 工具脚本（无工具的纯资源插件可省略）
        ├── characters/       # 以下均为可选：携带资源
        ├── scripts/
        ├── musics/
        ├── backgrounds/
        └── ambients/
```

数据目录位置：桌面发行版默认在程序旁的 `data/`，开发模式用项目根目录的 `data/`，Android 使用系统分配的应用数据目录（改文件需要 `MT管理器` 之类的工具）。参见 [安装与多平台部署](/guide/installation)。

放好后回到 `设置 → 插件`（切走再切回可刷新列表）即可看到。

::: warning 目录名必须等于 `manifest.id`
后端强制两者一致。手动改目录名会导致插件加载失败；要改名请同时改 manifest，或干脆重新导入。
:::

## 启用、授权与禁用

插件页每个条目的开关就是启用状态。启用时，宿主会把插件声明的工具**一并授权给默认角色组**，效果等同于在工具设置页手动打开对应开关；工具因此才会随主聊天下发给模型，也才能进入 Tool RAG 的候选池。禁用插件时授权一并收回。

::: danger 禁用携带角色的插件会删除存档
禁用插件会把它携带的角色从角色列表移除，并删除这些角色的全部存档与对话记忆——**重新启用也不会恢复**。只想让某个角色暂时不出现，请不要用「禁用插件」当开关。
:::

## 插件页上都有什么

| 区域 | 作用 |
| --- | --- |
| 名称 / 版本 / 描述 | 来自 `manifest.toml`，用于确认装的是哪个插件 |
| 启用开关 | 启停插件；存在错误时开关不可用 |
| 工具标签 | 该插件注册进工具列表的工具名 |
| WebSocket 连接 | 插件声明的外部连接及实时状态（未连接 / 连接中 / 已连接 / 错误） |
| 携带资源 | 展开后可对单条资源做隐藏、恢复、保留，见下节 |
| 环境变量 | 插件从进程环境白名单里读到的变量，只读 |
| 配置表单 | 插件声明 `config_schema` 时出现，填完点「保存」 |
| 删除 | 删除插件本体；已「保留」到游戏目录的资源不受影响 |

## 前置插件

插件可以通过 `depends_on` 依赖其他插件。依赖没满足时，开关会打不开，并给出原因：

| 提示 | 含义 |
| --- | --- |
| 缺少前置插件 | 依赖压根没装 |
| 前置插件未启用 | 装了但没打开，先去启用 |
| 前置插件形成循环依赖 | 互相依赖，无法确定启动顺序 |
| 插件的启动函数执行失败 | 插件 `startup` 入口报错，插件已被自动禁用 |

## 实战示例：把角色联机进 Minecraft

以内测版自带的「车万女仆桥接」（插件 id `mc_maid_bridge`）为例。它在本机和《车万女仆》之间架一条本地回环 WebSocket：你在游戏里说的话进对话，角色的回复变成女仆头顶的聊天气泡，模型还能直接指挥女仆行动。

::: warning 内测整合包
以下示例基于 LingChat v0.6.0 内测包，直接运行 `ling_chat.exe` 即可。**不要拿它直接替换已有存档的原版游戏**——内测版不稳定，容易丢存档。
:::

### 1. 准备好游戏侧

| 依赖 | 版本要求 |
| --- | --- |
| Minecraft | 1.21.1 |
| NeoForge | 21.1+ |
| 车万女仆 `touhou_little_maid` | 1.5.3+ |
| 桥接模组 `lingchat_maid_bridge` | 放进游戏 `mods/` 目录 |

图省事可以直接用 `Maid Adventure` 整合包（PCL 一键导入），里面已经带好 MC、暮色森林、一堆地形 mod 和女仆 mod。如果某些 mod 版本偏旧导致游玩异常，把整合包 `mod/` 里的替换一下即可。

### 2. 启用插件

打开 `设置 → 插件`，找到「车万女仆桥接」，打开开关。条目下方会列出它注册的 12 个工具（`maid_go_to`、`maid_sit_down`、`maid_attack`……）。启用即自动授权给默认角色组，不需要再去工具设置页点开关。

### 3. 按需填配置

| 配置项 | 默认 | 什么时候要动 |
| --- | --- | --- |
| 桥接模组地址 `ws_url` | `ws://127.0.0.1:48920` | 只有模组改过端口才需要改 |
| 女仆 UUID `maid_id` | 空 | 建议填（从模组面板复制）。留空则每次用到都现问游戏，游戏暂停时最长等 5 秒 |
| 你在 MC 里的用户名 `player_name` | 空 | 建议填，例如 `NoiQing_Ling`；留空时聊天里可能出现 MC 账号名 |
| 她最喜欢吃的东西 `favorite_food` | 空 | 填物品 id（逗号分隔，如 `cake`、`farmersdelight:cooked_rice`），你拿在主手时她会凑过来讨 |
| 同步游戏内气泡 `echo_to_game` | 开 | 不想让女仆头顶冒话就关掉 |
| 游戏内播放语音 `play_voice_in_game` | 关 | 想在 MC 里听到她说话：语音按女仆位置播放，本机静音 |
| 游戏窗口标题 `screen_window` | `Minecraft` | 只有改过窗口标题或用非原版启动器时才需要动 |
| 攒够几条事件先开口 `proactive_after_events` | 3 | 游戏里的变化攒够这么多条、且期间没人说话，就请角色主动开口；填 `0` 只记旁白 |

改完点「保存」。标着「改完在下一次游戏里说话（或重连）时生效」的字段需要等重连。

### 4. 打开主动对话（最容易漏的一步）

::: danger
**一定要打开主动对话**，否则女仆不会主动找你说话，也不会主动做事。这是 LingChat 的主动对话总开关，不是插件里的选项，见 [主动对话与屏幕感知](/manual/proactive-companion)。
:::

### 5. 把回复调成适合游戏里看的样子

在文本设置里切成**短句**模式，并打开**自动模式**。MC 的气泡放不下长段落，长回复会一句句刷屏。

## 安全提醒

插件脚本每次调用都在新的受限 Python 解释器中执行：不能直接读写文件系统、不能起子进程，环境变量只按 manifest 白名单注入。但这不代表插件「无害」：

- 插件可以通过 `call_tool` 调用**带写入能力**的已注册工具（加记忆、加待办、切场景等），沙箱目前不校验调用方身份；
- 插件可以发起 HTTP 请求、往对话里注入消息；
- 插件会往角色、剧本、场景里注入资源。

::: warning
装第三方插件前请确认来源。不信任的插件不要开，更不要直接塞进 `data/plugins/` 后手动启用。
:::

## 常见问题

**插件工具不生效？**
依次确认：插件已启用；角色在**默认角色组**里（移进其他角色组后拿不到插件工具，工具设置页也补不了授权）；当前是「玩家直接跟角色说话」的轮次——主动对话与剧本走固定工具快照，不含插件工具。

**想卸载但保留角色？**
先在「携带资源」里对角色点「保留」，把资源复制进游戏目录，再删除插件。直接禁用或删除插件会连带清掉插件角色及其存档。
